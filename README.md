# SIAM4 ExpoPass

เว็บกิจกรรมนิทรรศการของโรงเรียนสยามกลการ 4: ลงทะเบียน → รับทราบข้อมูลส่วนบุคคล → แบบประเมิน → แบบทดสอบ → เกียรติบัตร PDF ที่ตรวจสอบ QR ได้

## สิ่งที่ทำได้

- แอดมินจัดกิจกรรมหลายโครงการ แยกวัน เวลา สถานที่ สถานะ เกณฑ์ผ่าน และลิงก์ของแต่ละงาน
- แบบประเมินแบ่งด้านและคำถาม แบบคะแนน 1–5 ตัวเลือก คำตอบสั้น และคำตอบยาว
- ข้อสอบปรนัย 4 ตัวเลือก ถูก/ผิด ตอบสั้น ตรวจอัตโนมัติ ตั้งคะแนนและจำนวนครั้งที่ทำได้
- เครื่องมือเกียรติบัตร A4 แนวตั้ง/แนวนอน ลากวาง QR รูปภาพ ข้อความ ฟอนต์ Sarabun/Prompt/Kanit ผู้ลงนามพร้อมตำแหน่งและลายเซ็นได้ 3 คน
- PDF สร้างจากเทมเพลตเมื่อกดดาวน์โหลด **ไม่เก็บไฟล์ PDF** ใน Supabase; Storage เก็บเพียงรูปที่อัปโหลด
- QR มี token เดาสุ่ม เชื่อมหน้าแสดงชื่อ กิจกรรม วันที่ผ่าน เลขใบ และสถานะ; เลขใบออกด้วยธุรกรรมฐานข้อมูล
- ผู้รับค้นใบเก่าจากทุกกิจกรรมหลังยืนยันอีเมลที่ลงทะเบียนไว้; แอดมินเห็นสรุปตำแหน่ง จังหวัด แบบประเมินรายข้อ/ด้าน ผลข้อสอบ และส่งออก CSV

## ติดตั้ง Supabase

1. สร้างโปรเจกต์ **ใหม่** ใน Supabase เลือกภูมิภาคให้เหมาะกับโรงเรียน
2. เปิด SQL Editor และ Run เนื้อหาไฟล์ `supabase/schema.sql` เพียงครั้งเดียว **อย่ารันซ้ำบนฐานข้อมูลเดิม**
3. Authentication → Users: สร้างบัญชีแอดมินที่เข้าได้ด้วยอีเมลและรหัสผ่าน แล้วคัดลอก UUID ของบัญชีมา Run:

   ```sql
   insert into public.staff(user_id,role) values ('UUID-บัญชีแอดมิน','admin');
   ```

4. Authentication → URL Configuration: ใส่ Site URL ของเว็บและ Redirect URLs เช่น `https://USERNAME.github.io/REPOSITORY/**` เพื่อให้ลิงก์อีเมลค้นใบรับรองกลับเข้าเว็บได้
5. Project Settings → API: คัดลอก Project URL และ **Publishable key** ไปใส่ `.env` ตาม `.env.example` ห้ามใช้ secret/service-role key ในเว็บ

## ทดลองในเครื่อง

```bash
npm ci
cp .env.example .env
# แก้ค่า .env ให้ตรงกับ Supabase
npm run dev
```

เปิดเว็บ → ปุ่ม **แอดมิน** → ล็อกอิน → สร้างกิจกรรม → เพิ่มด้านประเมิน/ข้อสอบ → ออกแบบและบันทึกเกียรติบัตร → เปลี่ยนสถานะเป็นเผยแพร่ ทดสอบด้วยอีเมลอีกบัญชีหนึ่งและลองดาวน์โหลด/สแกน QR

## เผยแพร่บน GitHub Pages

วางไฟล์ใน root ของ repository แล้ว push ไป branch `main` ตั้ง Settings → Pages → Source = **GitHub Actions** เพิ่ม Repository Variables ที่ Settings → Secrets and variables → Actions:

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_PUBLISHABLE_KEY`

workflow `.github/workflows/deploy.yml` จะ build และ deploy ด้วย base path ของชื่อ repository โดยอัตโนมัติ ถ้าใช้โดเมนเฉพาะให้แก้ `VITE_BASE_PATH` ใน workflow เป็น `/` และปรับ Auth URL Configuration ให้ตรงโดเมนจริง

## ข้อมูลและข้อจำกัด

- ฐานข้อมูลเก็บข้อมูลผู้ร่วมและผลผ่าน เลขใบ เวอร์ชันเทมเพลตและ token ตรวจสอบ; ไม่มี PDF สะสม
- ภาพพื้นหลังและลายเซ็นอยู่ใน bucket สาธารณะเพื่อให้เว็บประกอบ PDF ได้ ไม่ควรอัปโหลดข้อมูลส่วนตัวลง bucket นี้
- แบบที่ออกใบแล้วถูกล็อกการแก้ไขในฐานข้อมูล การบันทึกแก้ไขครั้งใหม่จะสร้างเวอร์ชันใหม่ ใบเก่าจึงคงแบบเดิม
- คำตอบสั้นตรวจด้วยข้อความที่ตรงกับเฉลย/คำตอบทางเลือกหลังตัดช่องว่างส่วนเกินและไม่แยกตัวพิมพ์อังกฤษ; ยังไม่มีคิวตรวจด้วยคน
- ไฟล์ PDF เป็นภาพความละเอียดสูงของเกียรติบัตรเพื่อให้ฟอนต์ไทยแสดงเหมือนหน้าออกแบบ ตัวอักษรใน PDF อาจคัดลอกไม่ได้
- ใช้ HTTPS ของ GitHub Pages และกำหนดนโยบายการเก็บข้อมูลให้เหมาะกับโรงเรียนก่อนเผยแพร่ แยกความยินยอมเผยแพร่ซึ่งไม่บังคับจากการรับทราบข้อมูลเพื่อเข้าร่วม
- ระบบอีเมลค่าเริ่มต้นของ Supabase มีข้อจำกัดการส่ง ควรตั้ง SMTP และทดสอบจำนวนผู้เข้าชมจริงก่อนวันงาน; แผนฟรีอาจหยุดโปรเจกต์เมื่อไม่มีการใช้งาน
- ยังไม่มี CAPTCHA หรือ rate limit ที่ระดับ IP หากเปิด URL สู่สาธารณะวงกว้าง ควรเพิ่มก่อนงานที่เสี่ยงถูกส่งข้อมูลสแปม

## ทดสอบที่ทำแล้ว

`npm run build` ผ่าน และรัน schema/การลงทะเบียน/ประเมิน/ตรวจคะแนน/ออกเลขใบ/ตรวจ QR ใน PostgreSQL-compatible runtime ผ่าน การเชื่อมกับ Supabase ของโรงเรียน อีเมล รูปภาพ และการพิมพ์ PDF จริงต้องทดลองหลังใส่ค่าบัญชีของคุณ
